# Topology — accessibility waivers

Chart: the per-session Topology tab graph and the cross-session `/topology`
graph (both `role="group"` name `"Session topology graph"`).
Renderer component: `src/pages/SessionDetail/TopologyTab/TopologyRenderer.tsx`
(`TopologySvg` ≤ node ceiling, `TopologyCanvas` above it), reused by
`src/pages/Topology/Topology.tsx`.
D3 layout module: `src/viz/topology.ts` (+ the `?worker` force-layout worker
`src/viz/forceWorker.ts`).

The axe E2E pass (`tests/viz-a11y.spec.ts`, "Topology tab" + "/topology
(cross-session)") runs a GLOBAL axe scan on both routes under both themes and
asserts **zero serious/critical violations**. There are currently **no
per-selector axe exclusions** for the topology graph. This file records that the
topology Canvas mode is **keyboard-accessible** (no real gap).

## Canvas-mode keyboard access — NO gap

- Above the node ceiling the graph switches to `TopologyCanvas`
  (`TopologyRenderer.tsx` ~line 377). Like the timeline Canvas renderer, it
  provides a visually-hidden but focusable `<button>` fallback list — `<ul
  aria-label="Topology nodes">` (`TopologyRenderer.tsx` ~line 388), one `<button>`
  per node carrying the same accessible name + failure-% the SVG node shapes use.
  So every node IS reachable and operable by keyboard / screen reader.
- The click handler on the `<canvas>` is a pointer-only convenience over that
  complete DOM keyboard path. (At the time of writing the `<canvas>` click is not
  even lint-flagged — its handler sits on the `<canvas>` element, the
  jsx-a11y-interactive case — but the fallback list means there is no real gap to
  flag regardless.)
- The SVG renderer (`TopologySvg`, used at the default seed size) is fully
  keyboard-operable (each node is a `role="button"` `tabIndex={0}` with an
  `onKeyDown` handler, `TopologyRenderer.tsx` ~line 217/226), so both topology
  routes are axe-clean and keyboard-clean under the committed seed.

## Web-Worker note

The seeded-force layout runs in `src/viz/forceWorker.ts`, imported with Vite's
`?worker` suffix. That worker affects layout computation only; it renders no DOM
and has no a11y surface. (The `?worker` import is also the subject of an
`import/default` per-line eslint-disable in `TopologyTab.tsx` / `Topology.tsx` —
a build-time resolver false-positive, unrelated to a11y.)

## Policy for any future per-selector axe exclusion

If a third-party D3 SVG attribute ever trips a serious/critical axe rule on this
chart, exclude the **specific selector** in `tests/viz-a11y.spec.ts` via
`new AxeBuilder({ page }).exclude('<selector>')` and add an entry here with: the
excluded selector, the exact rule id, the rationale, and the upstream/owning
issue. **Never** disable an axe rule globally.
