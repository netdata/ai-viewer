# Waterfall — accessibility waivers

Chart: the Trace tab APM **waterfall** (`role="group"` name `"Trace waterfall"`).
Renderer component: `src/pages/SessionDetail/TraceTab/Waterfall.tsx`
(`WaterfallSvg` ≤ `SVG_SPAN_CEILING` spans, `WaterfallCanvas` above it).
D3 layout module: `src/viz/trace.ts`.

The axe E2E pass (`tests/viz-a11y.spec.ts`, "Trace tab") runs a GLOBAL axe scan
on this route under both themes and asserts **zero serious/critical violations**.
There are currently **no per-selector axe exclusions** for the waterfall — the
default seed renders the fully-accessible SVG path, which is axe-clean. This file
documents one **known a11y limitation** (a real gap, tracked) and the policy for
any future exclusion.

## Known limitation — Canvas-mode keyboard access (REAL gap, tracked)

- **What:** above `SVG_SPAN_CEILING` (`src/viz/trace.ts` = 400 ops) the waterfall
  switches from the SVG renderer to `WaterfallCanvas`
  (`Waterfall.tsx` ~line 463). The `<canvas>` is a single non-focusable image and
  the click handler is a pointer-only pixel hit-test (`Waterfall.tsx` ~line 449).
  **Unlike** the timeline Canvas renderer, `WaterfallCanvas` has **no
  visually-hidden focusable `<button>` fallback list**, so in Canvas mode a
  keyboard / screen-reader user **cannot select a span**.
- **Where the lint gate stands:** the two jsx-a11y rules
  (`click-events-have-key-events`, `no-noninteractive-element-interactions`) are
  disabled per-line on the Canvas wrapper `<div>` with an inline rationale
  (`Waterfall.tsx` ~line 473). The disable unblocks the gate; the gap is **not**
  silently accepted — it is recorded here and tracked as a follow-up.
- **Why it is not fixed in SOW-0012 Chunk D:** Chunk D's scope is to DOCUMENT the
  waiver. The actual fix — adding a focusable-span fallback list mirroring
  `TimelineRenderer` (`src/pages/SessionDetail/TimelineTab/TimelineRenderer.tsx`
  ~line 623, the `canvasFallbackList` `<ul aria-label="Timeline spans">`) — is the
  tracked follow-up.
- **Owning issue / follow-up:** SOW-0012 `## Followup` — "Canvas-mode
  keyboard-access gap" (`.agents/sow/current/SOW-0012-20260526-frontend-quality-stack.md`).
- **Why axe does not catch it:** axe cannot see inside a `<canvas>`; it has no DOM
  to assert keyboard operability against. The gap is real but invisible to both
  axe and (for the FlameGraph variant) the lint gate — see
  `src/viz/flamegraph/a11y.md`.
- **Default-seed exposure:** the committed E2E seed renders ≤ a few ops, so the
  SVG path is used and the route is axe-clean today. The gap only manifests on a
  trace with > 400 ops (no such fixture is committed yet).

## Policy for any future per-selector axe exclusion

If a third-party D3 SVG attribute ever trips a serious/critical axe rule on this
chart, exclude the **specific selector** in `tests/viz-a11y.spec.ts` via
`new AxeBuilder({ page }).exclude('<selector>')` and add an entry here with: the
excluded selector, the exact rule id, the rationale, and the upstream/owning
issue. **Never** disable an axe rule globally (no `.disableRules([...])` across
the whole page) — that would blind the gate for every other element.
