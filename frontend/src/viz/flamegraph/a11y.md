# FlameGraph — accessibility waivers

Chart: the Trace tab **flame-graph** (`role="group"` name `"Trace flame-graph"`).
Renderer component: `src/pages/SessionDetail/TraceTab/FlameGraph.tsx`
(`FlameSvg` ≤ `SVG_SPAN_CEILING` spans, `FlameCanvas` above it).
D3 layout module: `src/viz/trace.ts`.

The axe E2E pass (`tests/viz-a11y.spec.ts`, "Trace tab") runs a GLOBAL axe scan
on this route under both themes and asserts **zero serious/critical violations**.
There are currently **no per-selector axe exclusions** for the flame-graph — the
default seed renders the fully-accessible SVG path. This file documents one
**known a11y limitation** (a real gap, tracked) and the future-exclusion policy.

## Known limitation — Canvas-mode keyboard access (REAL gap, tracked, LINT-BLIND)

- **What:** above `SVG_SPAN_CEILING` (`src/viz/trace.ts` = 400 ops) the flame-graph
  switches from `FlameSvg` (fully keyboard-operable — every cell is a
  `role="button"` `tabIndex={0}` with an `onKeyDown` Enter/Space handler,
  `FlameGraph.tsx` ~lines 43–120) to `FlameCanvas` (`FlameGraph.tsx` ~line 124).
  In Canvas mode the `<canvas>` is a single non-focusable image and the click
  handler is a pointer-only pixel hit-test bound **directly to the `<canvas>`**
  (`FlameGraph.tsx` ~line 191/218). There is **no visually-hidden focusable
  `<button>` fallback list**, so a keyboard / screen-reader user **cannot select a
  cell** in Canvas mode.
- **Why this one is LINT-BLIND (important):** the `onClick` sits on the
  `<canvas>` element itself, and jsx-a11y treats `<canvas>` as an interactive /
  embedded element — so `click-events-have-key-events` /
  `no-noninteractive-element-interactions` do **not** fire. There is therefore
  **no eslint-disable line** marking this gap in the source (unlike
  `WaterfallCanvas`, whose `onClick` is on a wrapper `<div>` and IS flagged). The
  lint gate is a **blind spot** for canvas-on-`<canvas>` keyboard access; this
  file is the record that the gap exists.
- **Why it is not fixed in SOW-0012 Chunk D:** Chunk D DOCUMENTS the waiver. The
  fix — a focusable-span fallback list mirroring `TimelineRenderer`
  (`TimelineRenderer.tsx` ~line 623, `<ul aria-label="Timeline spans">`) — is the
  tracked follow-up.
- **Owning issue / follow-up:** SOW-0012 `## Followup` — "Canvas-mode
  keyboard-access gap" (`.agents/sow/current/SOW-0012-20260526-frontend-quality-stack.md`),
  which names BOTH `WaterfallCanvas` and `FlameGraph` and explicitly records that
  the lint gate is blind to this case.
- **Why axe does not catch it:** axe cannot inspect inside a `<canvas>`; there is
  no DOM to assert keyboard operability against.
- **Default-seed exposure:** the committed E2E seed renders ≤ a few ops, so the
  SVG path is used and the route is axe-clean today. The gap only manifests on a
  trace with > 400 ops (no such fixture is committed yet).

## Policy for any future per-selector axe exclusion

If a third-party D3 SVG attribute ever trips a serious/critical axe rule on this
chart, exclude the **specific selector** in `tests/viz-a11y.spec.ts` via
`new AxeBuilder({ page }).exclude('<selector>')` and add an entry here with: the
excluded selector, the exact rule id, the rationale, and the upstream/owning
issue. **Never** disable an axe rule globally.
