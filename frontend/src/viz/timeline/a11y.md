# Timeline — accessibility waivers

Chart: the Timeline tab video-editor lanes (`role="group"` name
`"Session timeline"`).
Renderer component: `src/pages/SessionDetail/TimelineTab/TimelineRenderer.tsx`
(`TimelineSvg` ≤ `SVG_SPAN_CEILING` spans, `TimelineCanvas` above it).
D3 layout module: `src/viz/timeline.ts`.

The axe E2E pass (`tests/viz-a11y.spec.ts`, "Timeline tab") runs a GLOBAL axe
scan on this route under both themes and asserts **zero serious/critical
violations**. There are currently **no per-selector axe exclusions** for the
timeline. This file documents the **lint** disable on the Canvas wrapper and
records that — unlike the waterfall and flame-graph — the timeline Canvas mode is
**keyboard-accessible** (no real gap).

## Canvas-mode keyboard access — NO gap (clean false-positive)

- Above `SVG_SPAN_CEILING` the timeline switches to `TimelineCanvas`
  (`TimelineRenderer.tsx` ~line 589). The `<canvas>` is a non-focusable image and
  the click handler is a pointer-only pixel hit-test, so the two jsx-a11y rules
  (`click-events-have-key-events`, `no-noninteractive-element-interactions`) are
  disabled per-line on the wrapper `<div>` with an inline rationale
  (`TimelineRenderer.tsx` ~line 596).
- **This is a clean false-positive, not a gap:** `TimelineCanvas` renders a
  visually-hidden but focusable `<button>` fallback list — `<ul aria-label=
  "Timeline spans">` (`TimelineRenderer.tsx` ~line 623), one `<button>` per
  viewport-culled span carrying the same accessible name the SVG bars use. So
  every visible span IS reachable and operable by keyboard / screen reader; the
  pointer hit-test on the canvas is a convenience layered over a complete DOM
  keyboard path. The cull bounds the list so a thousands-span timeline does not
  emit a DOM node per span.
- The SVG renderer (`TimelineSvg`, used at the default seed size) is itself fully
  keyboard-operable (each span shape is a `role="button"` `tabIndex={0}` with an
  `onKeyDown` handler), so the route is axe-clean and keyboard-clean under the
  committed seed.

## Policy for any future per-selector axe exclusion

If a third-party D3 SVG attribute ever trips a serious/critical axe rule on this
chart, exclude the **specific selector** in `tests/viz-a11y.spec.ts` via
`new AxeBuilder({ page }).exclude('<selector>')` and add an entry here with: the
excluded selector, the exact rule id, the rationale, and the upstream/owning
issue. **Never** disable an axe rule globally.
