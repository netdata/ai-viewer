# Design System (SOW-0073)

The single source of truth for ai-viewer's visual language. Established 2026-06-19 by SOW-0073; updated by every page-redesign SOW after.

## Layers

1. **Tailwind v4** — utility framework. `@tailwindcss/vite` plugin in `vite.config.ts`. CSS-first config (no `tailwind.config.js`); the theme lives in `@theme inline { ... }` blocks inside `src/theme/app.css`.
2. **Geist Sans + Geist Mono** — self-hosted via `@fontsource/*` (SIL OFL). No Google Fonts dependency. Imported at the top of `app.css`.
3. **Semantic CSS variables** — shadcn-style (`--background`, `--foreground`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`, `--card`, `--popover`, `--chart-1..5`, `--sidebar-*`, `--status-*`, `--source-*`). Defined per-theme on `:root` (dark default) and `:root[data-theme="light"]`.
4. **Tailwind `@theme inline` bridge** — maps the CSS variables to Tailwind utilities so `bg-background`, `text-foreground`, `border-border`, `text-status-running`, `bg-source-opencode` etc. all resolve correctly in both themes with zero JS.
5. **Legacy-token shim** (`--bg-primary`, `--accent`, `--space-*`, `--font-size-*`, `--shadow-*`, `--focus-ring`) — mapped to the new semantic variables. Kept so existing CSS Modules continue to work during the migration. Drop in a follow-up SOW once every CSS Module is replaced with Tailwind utilities.
6. **shadcn/ui primitives** — under `src/components/ui/`. 19 components (button, card, badge, input, label, separator, skeleton, tooltip, popover, dropdown-menu, select, toggle, toggle-group, sheet, scroll-area, command, dialog, textarea, input-group). Generated by `npx shadcn add <name>` with `components.json` configured for the radix-nova preset, neutral base, lucide icons, cssVariables on.
7. **App composition** — `<AppSidebar>` + `<AppTopbar>` in `src/components/Layout/`. The single source for nav, brand, live indicator, theme menu, search/command-palette trigger, filters sheet.

## Typography

- **Geist Sans** — UI body, buttons, table cells. Variable weight (400/500/600/700 from `@fontsource/geist-sans`).
- **Geist Mono** — tabular / code (timestamps, token counts, cost, IDs). 400/500 from `@fontsource/geist-mono`.
- **Type scale** — Tailwind defaults: `xs` (0.75 rem) for uppercase column headers with `tracking-wider`; `sm` (0.875 rem) for body; `base` (1 rem) for page titles + hero numbers; `lg`/`xl` for hero sections; `2xl` for the oversized Sessions / Topology page headers.
- **Numeric columns** — `font-variant-numeric: tabular-nums` so digits align under each other across rows. Applied to: timestamps, token counts, costs, durations, turn counts, op counts, failure counts.

## Spacing & radius

- 4 px base scale (Tailwind default): `1` (0.25 rem), `2` (0.5 rem), `3` (0.75 rem), `4` (1 rem), `6` (1.5 rem), `8` (2 rem). No 5, no 7 — half-steps are deliberate (avoid visual noise).
- Radius: `sm` (4 px), `md` (6 px), `lg` (10 px), `xl` (14 px). `lg` is the default for cards, modals, sheet; `md` for buttons, badges; `sm` for inputs.

## Motion

- Durations: 150 ms (micro), 200 ms (default), 300 ms (sheet open/close).
- Easings: Tailwind defaults (`ease-out` for entrances, `ease-in` for exits).
- `prefers-reduced-motion: reduce` disables every animation. Implemented at the document level in `app.css` and respected by individual components (e.g. StatusBadge pulse, LiveIndicator pulse).

### Page-level

The Sessions page (`pages/SessionsList/SessionsList.tsx`) is the design reference for every page-redesign SOW that follows. Pattern:

1. **Header** — large title, session-count subtitle, stats summary inline (semantic color per metric).
2. **Toolbar** — segmented controls for the main toggle (Primary/All), density, sort direction; inline active-filter count + Refresh button.
3. **Table** — sticky header with uppercase tracking-wide column labels; source-color left rail; zebra striping; hover row; tabular-nums on numerics; click-row-to-navigate; proper empty/loading/error states.
4. **Pagination** — "Load more" button at the bottom of the table (preserved from the old design; infinite-scroll is a follow-up).

## Accessibility

- All interactive elements have visible focus rings (`focus-visible:ring-2 focus-visible:ring-ring`).
- All icon-only buttons have `aria-label`s.
- Color is never the only signal (status uses icon + label; series in charts use a text legend; failures > 0 are also red).
- `prefers-reduced-motion` disables every animation.
- Tables have proper `<th scope="col">` semantics; sortable column headers are `<button>`s inside the `<th>`.
- The LiveIndicator carries its state in `aria-label` ("SSE status: Live" / "Connecting…" / etc.); the dot is `aria-hidden`.
- Tooltips use Radix TooltipPrimitive which is screen-reader-accessible.
- Axe-core runs on every Playwright spec (a11y gate); the redesigned Sessions page is axe-clean.

## Conventions

- **Status badge** — always `<StatusBadge status={s.status} />`. Never hand-roll a status pill.
- **Source badge / left rail** — use `var(--source-<id>)` derived from the `source_id`. Helper in `pages/SessionsList/SessionsList.tsx` (`sourceColorVar`).
- **Numeric column** — add `font-mono text-xs tabular-nums` to the `<td>` (or the parent `<tr>`).
- **Empty state** — `<div>` with an icon-in-circle + heading + description. Two flavors: filtered ("No sessions match these filters") and unfiltered ("No sessions yet"). See `SessionsEmpty` in `pages/SessionsList/SessionsList.tsx`.
- **Loading state** — `<Skeleton>` rows + skeleton header. See `SessionsSkeleton` in `pages/SessionsList/SessionsList.tsx`.
- **Error state** — `<ErrorState error={err} title="…" />` from `components/StatusViews/`. Carries the ApiError message verbatim.
- **Page header** — large title (`text-2xl font-semibold tracking-tight`), inline subtitle/count (`text-sm text-muted-foreground tabular-nums`), one-line description (`text-sm text-muted-foreground`), stats summary inline with semantic color per metric.
- **Toolbar** — segmented `<ToggleGroup>` for the main toggle; outline `<Button>` for one-shot actions; icon-only buttons get `aria-label` + tooltip.

## Anti-patterns

- Hand-rolled status pills (use `<StatusBadge>`).
- Raw color hex codes in components (always use the semantic tokens or Tailwind utilities).
- Numeric columns without `tabular-nums`.
- Borders without `border-border` (use the token, not a raw color).
- Pure-color error/success indicators (must pair color with text + icon).
- Sortable column headers rendered as `<th>` text (must be `<button>` for keyboard).
- Unicode glyphs as icons (use lucide-react).
- Default browser focus rings (use the design system focus ring).
- Animation without `prefers-reduced-motion` consideration.
- `console.log` left in code.

## Maintenance

- Adding a new primitive: `npx shadcn@latest add <name>` (the components.json captures the preset). Then patch for `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` if the upstream has TS errors.
- Adding a new token: edit `src/theme/app.css` BOTH in the `:root` block (dark) AND in the `:root[data-theme="light"]` block, AND add the mapping in the `@theme inline` block.
- Adding a new page: copy the Sessions page pattern (header + toolbar + table + states). Use `<AppSidebar>` + `<AppTopbar>` already in place. Don't introduce a new layout pattern.
- Adding a new icon: lucide.dev → search → import from `lucide-react`. Tree-shaking is automatic.
